# Contributing to NeuRodent

`CONTRIBUTING.md` is the canonical contributor guide for this repository.
Documentation pages in `docs/contributing/` redirect here.

## Prerequisites

- Python 3.10+
- [uv](https://docs.astral.sh/uv/getting-started/installation/) (recommended)
- `make` (optional, for convenience commands)

## Quick Start

```bash
git clone https://github.com/josephdong1000/neurodent.git
cd neurodent
make setup
```

`make setup` runs:

- `uv sync --all-extras` (installs dependencies)
- `uv run pre-commit install` (installs git hooks)

## Manual Setup

Without `make`:

```bash
git clone https://github.com/josephdong1000/neurodent.git
cd neurodent
uv sync --all-extras
uv run pre-commit install
```

Without `uv`:

```bash
git clone https://github.com/josephdong1000/neurodent.git
cd neurodent
pip install -e ".[dev]"
pre-commit install
```

## Common Makefile Commands

- `make setup`: install dependencies + pre-commit hooks
- `make test`: run test suite with pytest
- `make docs`: build docs to `docs/_build/html`
- `make docs-live`: build docs with live reload
- `make clean`: remove build artifacts

## Pull Request Process

1. Fork the repository and create a branch for your feature or bug fix.
2. Make your changes and add/adjust tests when applicable.
3. Ensure tests pass and documentation builds successfully.
4. Open a pull request with a clear description of the change.

## Running Tests

```bash
make test
# or:
uv run pytest
```

Run with coverage:

```bash
uv run pytest --cov=neurodent
```

Run integration tests only:

```bash
uv run pytest tests/integration/ -v -m integration
```

## Pipeline Testing Strategy

NeuRodent validates the Snakemake pipeline at three levels:

1. **Component integration tests (pytest)**  
   Exercises core pipeline building blocks with a tiny synthetic NWB dataset.
2. **Snakemake DAG dry-run**  
   Validates Snakefile/config/rule resolution without processing data.
3. **Snakemake real run (GitHub Actions, mini_real dataset)**  
   Validates end-to-end processing in CI.

Quick commands:

```bash
# DAG validation only
NEURODENT_DATASET=example uv run snakemake --dryrun

# Full pipeline run on committed mini dataset
NEURODENT_DATASET=mini_real uv run snakemake --cores all

# Component integration tests
uv run pytest tests/integration/ -v -m integration
```

## Example Dataset for Pipeline Testing

The repository includes test infrastructure for lightweight pipeline validation:

- Synthetic dataset generated by `create_synthetic_dataset()` in
  `tests/integration/generate.py`
- Fixture wrapper in `tests/conftest.py`
- Integration flow examples in `tests/integration/test_snakemake_flow.py`

Mini real recordings are committed under `.tests/integration/data/` and exercised by
`TestMiniRealDataset`.

```bash
uv run pytest tests/integration/ -v -k TestMiniRealDataset
```

Related configs:

- `config/datasets/mini_real.yaml`
- `config/samples_mini_real.json`

## Pre-commit Hooks

NeuRodent uses [pre-commit](https://pre-commit.com/) hooks to maintain code quality.
Hooks run automatically before each commit.

`nbstripout` removes outputs from documentation notebooks in `docs/` to keep history
clean and reduce merge noise. Notebooks in `notebooks/` are excluded from stripping.

Run hooks manually:

```bash
uv run pre-commit run --all-files
```

## Validation Scripts (Cluster / Real Data)

Validation scripts live in `scripts/` and are intended for real data checks (often on
cluster environments).

### Dask vs Serial Spike Detection Consistency

Run:

```bash
uv run python scripts/validate_dask_serial_spike_consistency.py \
  --recording-folder "/path/to/real/recording" \
  --verbose
```

Use this after modifying
`src/neurodent/core/frequency_domain_spike_detection.py`.

Expected behavior:

- Identical spike indices at sample precision across modes
- Exit code `0` when identical, `1` when different

## Writing New Validation Scripts

When adding scripts in `scripts/`:

- Provide CLI help via `argparse`
- Add a comprehensive module docstring and usage examples
- Exit with `0` on success and `1` on failure
- Follow project style conventions and use informative errors
